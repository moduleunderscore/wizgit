# Instrucciones del proyecto Wizard

Usar `$wizard-builder` para estrategia, producto, automatización, frontend, copy, QA y entrega de este proyecto.

## Antes de construir

1. Leer `docs/01-brief.md` y `docs/02-diagnostico.md`.
2. Consultar los demás documentos numerados según la tarea.
3. Tratar los hechos específicos y verificados de este repositorio como autoridad sobre preferencias generales.
4. Marcar información faltante como `[PENDIENTE]`, supuestos como `[HIPÓTESIS]` y métricas futuras como `[OBJETIVO]`.

## Estándar de trabajo

- Resolver la fricción real, no solo producir la forma solicitada.
- Mantener visible el mecanismo, la fuente de verdad, las excepciones, el responsable y la métrica.
- No inventar clientes, resultados, certificaciones, QA, cumplimiento ni testimonios.
- Evitar frontend SaaS genérico. Definir una dirección de entorno clara y propia antes de implementar una interfaz material.
- Preservar cambios existentes y seguir las validaciones nativas del repositorio.
- Registrar decisiones que cambien alcance, arquitectura, costo, seguridad, operación o propiedad.
- No declarar listo lo que no se probó; registrar evidencia en `docs/08-prueba-de-fuego.md`.
- Entregar al cliente control y continuidad conforme a `docs/09-entrega-orbe.md`.

No copiar aquí la metodología completa: vive en `$wizard-builder`.
